# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static marketing site (Spanish, `lang="es"`) for "Los Cristales", a travel agency in Tingo María, Peru (legal entity: CORPORACIÓN TULUMAYO MYSTIC S.A.C.). Plain HTML + one shared stylesheet + one vanilla JS file, plus one PHP form handler (`enviar.php`). No build step, no package manager, no tests, no linter.

## Commands

- Preview: `python3 -m http.server` from the repo root (port 8000; if "Address already in use", a server is already running — reuse it or pick another port).
- Syntax check JS: `node --check script.js`.
- Visual checks: headless Chrome screenshots (`--headless=new --screenshot`). It enforces a ~500px minimum window width, so check mobile by screenshotting a temporary wrapper page with 390px iframes (delete it afterwards). `--dump-dom` renders no frames, so CSS transitions never progress there.
- Deploy: **every push to `main` deploys to production** (cPanel over FTPS, `.github/workflows/deploy.yml`; credentials live in GitHub secrets `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`). The workflow excludes `.git*`, `.github/`, `.atl/`, `odd/`, `.claude/`, `.DS_Store`, `skills-lock.json` and `CLAUDE.md`. Work on feature branches; merge to `main` or push only when a production release is intended.

## Workflow

- Git repo with work on feature branches; work is tracked through Gentle AI ODD feature documents in `odd/tasks/` (mirrored in Engram) and reviewed via `gentle-ai review` (receipt-driven development is on). `.atl/` is a generated local skill registry and is gitignored.

## Architecture

- `styles.css` is the single stylesheet, following the "Terra" design system (user-supplied spec, brand-agnostic parts only): light-by-default canvas (`--lienzo` #FFFFFF, #2D3436 text, soft surfaces #F3F5F8/#F6F8FA, one soft `--sombra` on light cards) in `:root` / `:root[data-theme="light"]` with a full dark theme (Deep Slate #2D3436) under `:root[data-theme="dark"]`. Teal `--teal` #008080 is the fill of primary actions (`.boton`, `.boton.verde`, form submits); small teal text uses `--enlace` (#5FC9C9 dark / #006B6B light) for AA contrast; Aged Gold `--oro` #C4A77D (`--oro-texto` for text/icons) is for accents: eyebrows, labels, badges, icons, footer headings, the header "Reservar" CTA's glowing border and the tour-card underline. Mist Gray #F5F6FA for subtle backgrounds/dividers. The home hero, tour covers, footer, top bar, lightbox and tour cards stay dark in both themes (they re-declare the dark tokens). Fonts: Playfair Display 600 (`--fuente-titulo`, headings) and Lato 400/700 (`--fuente`, body/UI) from Google Fonts via `<link>`. Theme toggle `.tema-toggle` in every header (fixed name "Tema claro", `aria-pressed` = light is active, localStorage key `tema`, default light, only `"dark"` is saved to override; an identical inline script in every `<head>` sets `data-theme` and the theme-color meta before paint; hidden without JS). Header: logo left, centred nav, toggle + gold-bordered "Reservar" → contacto.html right; transparent over the home hero (`body.inicio`, `.dinamica`/`.solida` from the scroll loop), solid elsewhere. Animations per spec: 300ms page fade, button hover darken + scale 1.02, image zoom 1.05, reveal fade + translateY(20px). Class names and tokens are in Spanish.
- Icons: every icon is an inline SVG with class `ico` (viewBox 0 0 24 24, stroke-width 1.75 from `.ico`, round caps/joins, `currentColor`, `aria-hidden`); each context only sets its size. No emoji or text glyphs as icons (script.js builds the lightbox buttons with the same SVGs). Shared-chrome icons (top bar, menu, toggle, TOURS chevron, WhatsApp, footer) must stay identical on all 11 pages.
- Legacy aliases `--gris`, `--divisor`, `--verde-oscuro` must stay in `:root`: `libro-de-reclamaciones.html` uses them in inline styles.
- `script.js` (loaded with `defer` on every page, one IIFE with commented sections) adds progressive enhancements only; pages must stay usable without it. All scroll effects share one passive scroll/resize listener and one `requestAnimationFrame`, skip off-screen elements, and write only CSS custom properties (`--progreso`, `--luz`, `--zoom`, `--zoom-portada`, `--desplazar`) that CSS maps onto `transform`/`translate`, so they never fight the CSS entrance animations on `scale`/`opacity`. Features: header hides on scroll down / shows on scroll up (never while the mobile menu is open or focus is inside), scroll-linked hero zoom/dim, the home hero crossfade slider, the "Próximamente" slider buttons (`.carrusel`), word-by-word highlight of `.declaracion` (screen readers get one hidden full copy), scroll-linked image zoom, staggered reveals (JS adds `.revelar` + `--i`; observer threshold 0), the gallery lightbox (hijacks `.galeria a`), and the form enhancement (both forms submit to `enviar.php` with `fetch` + `Accept: application/json`, show the result in `.estado-formulario`, and fall back to a normal submit on network failure).
- Interaction polish (from the `.claude/skills` design skills): `--salida` (`cubic-bezier(0.23, 1, 0.32, 1)`) is the ease-out for UI responses (press, hover lift, header show/hide, submenu, lightbox) and stays under ~300ms; `--curva` is for cinematic entrances. Pressables get a `scale` on `:active` (iOS needs the passive no-op `touchstart` listener in `script.js`). Decorative `:hover` rules live inside `@media (hover: hover) and (pointer: fine)`, except the desktop submenu open-on-hover (iPad users reach it via first-tap hover). Heroes use `svh` and the lightbox `dvh`, each with a `vh` fallback; `prefers-reduced-transparency` swaps glass for solid surfaces. Every page has `theme-color` #FFFFFF (the inline head script switches it to #2D3436 for a saved dark choice) and `color-scheme` "light dark" in `<head>`. `.revelar` sets per-property transitions so it doesn't clobber the element's own hover/press transitions.
- Entrance animations (page fade, hero `.mascara` lines, tour cover title) are CSS-only with fill-mode so they also run without JS. All motion is disabled under `prefers-reduced-motion` in CSS and JS (JS also reacts to live preference changes). Headless-Chrome checks of animations are unreliable (first-frame captures, smooth scroll and iframe IntersectionObserver don't advance): pause animations via `getAnimations()`, use `scrollTo({behavior:'instant'})`, or verify in a real browser.
- There is no templating or include system. The top bar, header/nav, footer, floating WhatsApp button (`.wa-flotante`) and script tag are **copy-pasted into all 11 HTML pages**. Any change to them must be applied everywhere; verify with `grep -c` across `*.html`. Legal pages contain a second `</ul></nav>` (`.otras-politicas`), so scripted nav edits must anchor on `<ul class="menu">`.
- Footer (`.pie-grid`, 4 columns on desktop, 2 under 1024px, 1 under 560px): "Datos de la empresa", "Contacto", "Políticas" (the three legal documents by their titles in sentence case + "Políticas de prevención ESNNA") and "Atención al cliente" ("📖 Libro de reclamaciones", "Créditos de fotos").
- Nav: INICIO, TOURS (submenu), CONTACTO. `index.html` uses `#tours`; other pages use `index.html#tours`. The mobile menu is a CSS checkbox toggle (`#menu-toggle:checked ~ nav .menu`; the menu is inside `<nav>`, not a sibling).
- Page types:
  - Home `index.html`: dark hero (eyebrow + h1 "Más allá de la selva." with a JS typewriter entrance — screen readers get one hidden full copy, no-JS keeps the line-rise — vignetted photo slider with a bottom scrim, glass bar with the teal "Reservar"), the "Próximamente" showcase (`section.proximamente`, directly after the hero: large photo cards), "Lo principal." fact cards (gold line icon chips), `.declaracion` statement, `.grid-tours` as 3 square photo cards with a gold underline on hover/focus-visible, contact CTA band. Every fact/number must come from the tour pages.
  - Tour pages (`parque-nacional-tingo-maria`, `laguna-de-los-milagros`, `catarata-honolulo`): `.portada-tour` (background image via inline `style`), `.migas`, `.itinerario`, `.galeria`, `.acciones` with a tour-specific prefilled WhatsApp link. Adding a tour means: new page, a card in `index.html`, and a submenu entry in every page's nav.
  - `contacto.html`: two columns — "Contáctanos." (address, phone, email, WhatsApp with gold line icons; no hours/map) and "Envíanos un mensaje." card with `form.contacto#form-contacto` posting to `enviar.php` (see Forms). JS live validation on both forms (`noValidate`, red/green borders, `aria-invalid` + linked text hint, focus first invalid); a successful contact fetch replaces the form with a focused success panel ("Enviar otro mensaje" resets it).
  - `creditos.html` ("Créditos de fotos"): legal-page layout listing every third-party photo (thumbnail, page that uses it, author, linked license, linked source). Linked from every footer's "Atención al cliente" column.
  - Legal pages: `terminos-y-condiciones` ("Términos y condiciones de uso y contratación"), `politicas-de-pago` ("Políticas de cobro, cancelación y reembolso"), `politicas-de-privacidad` ("Política de privacidad y protección de datos personales", one combined policy; the old `proteccion-de-datos-personales.html` was merged into it and `.htaccess` 301-redirects it there), `prevencion-esnna`, `libro-de-reclamaciones` (Peruvian regulatory requirement; its `form.reclamo` posts to `enviar.php`, which generates a claim number `LR-YYYYMMDD-HHMMSS-XXXX` and emails the consumer a copy, an Indecopi requirement).
- Home hero slider: `.hero-medio` (`role="region"`, `aria-roledescription="carrusel"`) wraps `figure.hero-foto > .hero-diapositivas` (takes the scroll zoom/dim and entrance) with stacked `img.hero-diapositiva` slides, plus the glass pause/play `.hero-pausa` (a sibling outside the masked figure, `hidden` until JS starts rotation; it swaps `aria-label` "Pausar fotos"/"Reanudar fotos"). Only `.activa` is visible (the first slide carries it in the HTML, so no-JS shows it); `script.js` crossfades by opacity every 5.5s (the outgoing slide stays opaque as `.saliente` under the incoming one) and holds while paused, the tab is hidden, the hero is off-screen, the pointer/keyboard focus is on the button, or under reduced motion (button hidden). To add a slide: another `<img class="hero-diapositiva" ... loading="lazy" decoding="async" fetchpriority="low" aria-hidden="true">` with an accurate Spanish `alt`, optional inline `--encuadre` (desktop `object-position`) and `--encuadre-movil` (square mobile crop); keep the first slide eager (LCP). To remove one, delete its `<img>`. Slides must show the real places of the tours/Tingo María; third-party photos must be credited in `creditos.html`.
- Home "Próximamente" (`section.proximamente`, directly after the hero, before "Lo principal."; header is `.titulo-proximamente`): announces a new destination whose name is not known yet; copy describes only what the photos show (no name, dates, prices or location). Below the `.titulo-seccion` sits `.carrusel`: a full-bleed native scroll-snap track `.carrusel-pista` (`role="region"`, `tabindex="0"`, hidden scrollbar, `overscroll-behavior-x: contain`) with `ul.carrusel-lista > li.carrusel-tarjeta` (one fixed height; portrait cards 3:4, `.horizontal` cards 4:3 capped at 84cqw; `object-fit: cover`). The gutter uses `cqw` (the section is a size container) so the first card lines up with `.contenedor`, with a `100vw` fallback line. Touch, trackpad and arrow keys scroll it natively; `script.js` only un-hides `.carrusel-controles` (glass prev/next buttons that jump to the neighbouring card's snap point, smooth or instant under reduced motion, disabled at the ends). To name the place once known: replace "Un nuevo destino." in `#titulo-proximamente` (there is a TODO comment), keep the "Próximamente" eyebrow, and update the track's `aria-label`; when the destination becomes a real tour, follow "Adding a tour" and remove or repurpose the section. Adding a photo: another `li.carrusel-tarjeta` (add `.horizontal` for landscape) with `width`/`height`, `loading="lazy" decoding="async"` and an accurate Spanish `alt`.
- Forms: both forms `action="enviar.php" method="post"` (urlencoded) with hidden `formulario` (`contacto` | `reclamo`). `enviar.php` (PHP 7.4+, no dependencies, sent with PHP `mail()` on the cPanel host) whitelists fields per form in `definicion_campos()` — every input `name` must match a key there (ASCII snake_case), so adding/renaming a field means editing both. Recipient is the `DESTINO` constant at the top: `mistyctulum@gmail.com` for both forms (business decision). `From`/envelope sender is fixed `no-reply@turismoloscristales.com`; visitor data only reaches headers as a validated `Reply-To`. Spam controls: honeypot `campo_control` (`.campo-trampa`, silently accepted and dropped), minimum fill time from the hidden `tiempo` field (ms on page, set by `script.js`; skipped without JS), and a per-IP rate limit (5 per 10 min) in `sys_get_temp_dir()` that fails open. Without JS it answers `303` to `<page>#enviado` / `#error`, shown by `.aviso-envio:target` blocks; with JS it answers JSON `{ok, message}`. PHP is not installed locally and the preview server is static: `enviar.php` can only be verified after deploy with a real submission (check delivery/spam folder and SPF/DKIM for the From domain).
- Images: tour photos in `img/` named `<prefix>-NN.jpg` (`pntm` = Parque Nacional, `lagu` = Laguna, `honol` = Honolulo, `tingo` = general Tingo María scenery, `prox` = the upcoming "Próximamente" destination; business-supplied photos, EXIF/GPS stripped, not listed in `creditos.html`). Logos/favicon and the two ESNNA images sit in the repo root. `pntm-10`–`pntm-12` and `tingo-01`–`tingo-03` are third-party photos (CC BY-SA 4.0 / Unsplash License): any third-party image must be listed in `creditos.html` with author, linked license and linked source, and never be presented as a different place; no credit text goes on or next to the photos. `img/honol-01.jpg` and `img/honol-09.jpg` carry third-party watermarks ("Marca Tingo María", photo credit "Marx Fuentes") and are no longer used anywhere: keep it that way, and never crop or mask a watermark.
