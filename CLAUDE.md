# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static marketing site (Spanish, `lang="es"`) for "Los Cristales", a travel agency in Tingo María, Peru (legal entity: CORPORACIÓN TULUMAYO MYSTIC S.A.C.). Plain HTML + one shared stylesheet + one vanilla JS file. No build step, no package manager, no tests, no linter.

## Commands

- Preview: `python3 -m http.server` from the repo root (port 8000; if "Address already in use", a server is already running — reuse it or pick another port).
- Syntax check JS: `node --check script.js`.
- Visual checks: headless Chrome screenshots (`--headless=new --screenshot`). It enforces a ~500px minimum window width, so check mobile by screenshotting a temporary wrapper page with 390px iframes (delete it afterwards). `--dump-dom` renders no frames, so CSS transitions never progress there.
- Deploy: **every push to `main` deploys to production** (cPanel over FTPS, `.github/workflows/deploy.yml`; credentials live in GitHub secrets `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`). The workflow excludes `.git*`, `.github/`, `.atl/`, `odd/`, `.claude/`, `.DS_Store`, `skills-lock.json` and `CLAUDE.md`. Work on feature branches; merge to `main` or push only when a production release is intended.

## Workflow

## Architecture

- `styles.css` is the single stylesheet, following an Apple-style dark design: pure black canvas `--lienzo`, `--carbon` (#1d1d1f) elevated cards, silk `--seda` (#f5f5f7) text, muted `--ceniza` (#86868b), and alternating light bands (`#f5f5f7` with dark text, e.g. the home tours section). Color is rationed: `--azul-accion` (#0071e3) is the FILL of exactly one primary content CTA per page (`.boton` / `.boton.verde`: home = the hero glass bar's "Reservar", tours = WhatsApp, contacto and libro = submit) plus focus rings; `--azul-enlace` (#2997ff) is for text links only; the chip gradient only on the small `.numero` badges. Everything else is achromatic. No box-shadows anywhere; elevation comes from tone, 28px card radius, and frosted glass (`rgba(66,66,69,.72)` + `backdrop-filter: blur(20px)`) on the hero glass bar (`.barra-vidrio`), nav, WhatsApp float and lightbox controls. Buttons are 9999px pills (`.boton` blue, `.boton.fantasma` ghost, `.boton.claro` light); inputs are pills (textareas 28px). Type: system SF Pro (`-apple-system`) with Inter 400/600 from Google Fonts as fallback; weights 400 and 600 only (never 700); large headings use negative tracking. The full-color logo sits on a small light chip in the nav because its greens vanish on black. Class names and tokens are in Spanish.
- Legacy aliases `--gris`, `--divisor`, `--verde-oscuro` must stay in `:root`: `libro-de-reclamaciones.html` uses them in inline styles.
- `script.js` (loaded with `defer` on every page, one IIFE with commented sections) adds progressive enhancements only; pages must stay usable without it. All scroll effects share one passive scroll/resize listener and one `requestAnimationFrame`, skip off-screen elements, and write only CSS custom properties (`--progreso`, `--luz`, `--zoom`, `--zoom-portada`, `--desplazar`) that CSS maps onto `transform`/`translate`, so they never fight the CSS entrance animations on `scale`/`opacity`. Features: header hides on scroll down / shows on scroll up (never while the mobile menu is open or focus is inside), scroll-linked hero zoom/dim, word-by-word highlight of `.declaracion` (screen readers get one hidden full copy), scroll-linked image zoom, staggered reveals (JS adds `.revelar` + `--i`; observer threshold 0), counters on `[data-contar]` (the real value stays in the HTML; reset to 0 only near the viewport), the gallery lightbox (hijacks `.galeria a`), and the contact form (composes a WhatsApp message).
- Interaction polish (from the `.claude/skills` design skills): `--salida` (`cubic-bezier(0.23, 1, 0.32, 1)`) is the ease-out for UI responses (press, hover lift, header show/hide, submenu, lightbox) and stays under ~300ms; `--curva` is for cinematic entrances. Pressables get a `scale` on `:active` (iOS needs the passive no-op `touchstart` listener in `script.js`). Decorative `:hover` rules live inside `@media (hover: hover) and (pointer: fine)`, except the desktop submenu open-on-hover (iPad users reach it via first-tap hover). Heroes use `svh` and the lightbox `dvh`, each with a `vh` fallback; `prefers-reduced-transparency` swaps glass for solid surfaces. Every page has `theme-color` #000000 and `color-scheme` dark in `<head>`. `.revelar` sets per-property transitions so it doesn't clobber the element's own hover/press transitions.
- Entrance animations (page fade, hero `.mascara` lines, tour cover title) are CSS-only with fill-mode so they also run without JS. All motion is disabled under `prefers-reduced-motion` in CSS and JS (JS also reacts to live preference changes). Headless-Chrome checks of animations are unreliable (first-frame captures, smooth scroll and iframe IntersectionObserver don't advance): pause animations via `getAnimations()`, use `scrollTo({behavior:'instant'})`, or verify in a real browser.
- There is no templating or include system. The top bar, header/nav, footer, floating WhatsApp button (`.wa-flotante`) and script tag are **copy-pasted into all 11 HTML pages**. Any change to them must be applied everywhere; verify with `grep -c` across `*.html`. Legal pages contain a second `</ul></nav>` (`.otras-politicas`), so scripted nav edits must anchor on `<ul class="menu">`.
- Nav: INICIO, TOURS (submenu), CONTACTO. `index.html` uses `#tours`; other pages use `index.html#tours`. The mobile menu is a CSS checkbox toggle (`#menu-toggle:checked ~ nav .menu`; the menu is inside `<nav>`, not a sibling).
- Page types:
  - Home `index.html`: black hero (eyebrow + h1 ending with a period, vignetted photo, frosted glass bar with the single blue CTA), "Lo principal." fact cards, `.declaracion` statement, "En cifras." stats, `.grid-tours` on a light band, contact CTA band. Every fact/number must come from the tour pages.
  - Tour pages (`parque-nacional-tingo-maria`, `laguna-de-los-milagros`, `catarata-honolulo`): `.portada-tour` (background image via inline `style`), `.migas`, `.itinerario`, `.galeria`, `.acciones` with a tour-specific prefilled WhatsApp link. Adding a tour means: new page, a card in `index.html`, and a submenu entry in every page's nav.
  - `contacto.html`: contact feature blocks, dark WhatsApp card (`.tarjeta-whatsapp`), and `form.contacto#form-contacto` in a dark band. With JS it opens `wa.me` with a composed message (and always shows a fallback link, since `window.open(..., 'noopener')` can't detect popup blocking); without JS it falls back to a `mailto:` post.
  - Legal pages: `terminos-y-condiciones`, `politicas-de-pago`, `politicas-de-privacidad`, `proteccion-de-datos-personales`, `prevencion-esnna`, `libro-de-reclamaciones` (Peruvian regulatory requirement; its claims form posts via `mailto:` to a different inbox than the contact form).
- Images: tour photos in `img/` named `<prefix>-NN.jpg` (`pntm` = Parque Nacional, `lagu` = Laguna, `honol` = Honolulo). Logos/favicon and the two ESNNA images sit in the repo root. `img/honol-01.jpg` and `img/honol-09.jpg` carry third-party watermarks ("Marca Tingo María", photo credit "Marx Fuentes"): don't use them as feature images, and never crop or mask a watermark.
